# Guía de contribución

**Versión documental:** V2.0

Este repositorio debe conservar evidencia verificable de la participación individual de cada integrante del equipo Capstone.

## Responsabilidades acordadas

- Matías Garrido: documentación y requerimientos.
- Rafael Oteiza: gestión, arquitectura, base de datos y backend.
- Luis Arenas: frontend Web y aplicación Mobile.

La distribución define responsabilidad principal, pero permite colaboración y revisión cruzada.

## Flujo de trabajo

1. Cada integrante trabaja con su propia identidad Git.
2. Los commits deben describir cambios reales y atribuibles.
3. Las ramas/PR pueden utilizarse para trabajo colaborativo y revisión.
4. No se deben crear commits atribuidos artificialmente a otra persona.

## Preparación local

Los archivos `.env` y las claves de servicio son locales y no se versionan. El backend puede configurarse a partir de `03_Backend/pmp-api/.env.example`.

## Evidencia Capstone

Commits, revisiones, código y documentos vinculados a cada entrega constituyen la evidencia individual. La organización declarada en README/CODEOWNERS no sustituye la contribución verificable.
